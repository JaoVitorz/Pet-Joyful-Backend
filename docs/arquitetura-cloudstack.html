GitHub → Actions (build / Jest / cobertura) → SonarCloud Quality Gate → Docker build e scan → Docker Hub (digest) → runner privado → HML → validação HTTP → PROD → verificação e rollback

Atual: backend publica imagem e solicita deploy no Render. Proposto: deploy em VMs privadas CloudStack, com espera pela saúde do serviço. Manter Winston / Better Stack e Gemini. SonarCloud já existe; SonarQube próprio é opcional.

Antes de publicar

  1. Corrigir a URL pública do frontend: o navegador não resolve backend:5000. Preferir /api com proxy e revisar variáveis Next.js no build.
  2. Retirar MongoDB da internet, criar usuário limitado e montar disco persistente.
  3. Criar readiness que detecta banco indisponível; a rota atual pode responder sem MongoDB.
  4. Separar HML e PROD, guardar segredos e automatizar deploy com rollback por digest.
  5. Ensaiar backup e restauração antes de migrar Atlas; validar dependências dos microsserviços externos.
  6. Para HA, distribuir VMs em hosts físicos distintos e testar entrada, aplicação e eleição do banco.

Recursos de VPN, NAT e balanceamento dependem do network offering. Dois containers ou VMs no mesmo host não eliminam a falha desse host. Três membros MongoDB não substituem backup. As metas de disponibilidade do README ainda precisam de testes.

Escopo e evidências

README, Compose, Dockerfile, package.json, workflow, Sonar e código do backend foram lidos. Frontend Next.js e serviços externos seguem a descrição do README; seus códigos não foram inspecionados. O estado remoto não foi testado. Os diagramas são uma proposta de arquitetura, não uma infraestrutura já provisionada.
