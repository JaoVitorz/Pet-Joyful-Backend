PLANO DE IMPLANTAÇÃO · CLOUDSTACK · 06/10/2026

Como colocar o Pet Joyful inteiro em nuvem

Do acesso à infraestrutura até os usuários acessarem o projeto pelo domínio HTTPS. Este plano prepara front, backend, MongoDB e os microsserviços necessários; cada etapa mostra a execução, as tecnologias, o desafio e o critério de conclusão.

Três marcos de entrega

1. HML com todas as funcionalidades → 2. PROD com dados migrados, CI/CD e backup → 3. Alta disponibilidade testada.

Se HA for requisito de lançamento, concluir a etapa 12 antes de abrir produção na etapa 11. CloudStack precisa existir em uma instituição ou provedor; a Apache não oferece a conta de hospedagem.

01

Definir acesso e escopo

Confirmar nuvem CloudStack da instituição/provedor, conta, zona, cotas, IP público, domínio, orçamento e responsável pela operação. Inventariar frontend, backend, MongoDB, eventos, perfil/álbuns e uploads.

TECNOLOGIAS
CloudStack / GitHub / inventário de dependências

Desafio

CloudStack precisa de infraestrutura disponível; os três containers não cobrem necessariamente todas as funções.

Avançamos quando

Acesso e capacidade confirmados; lista de serviços e dados aprovada.

02

Preparar aplicação e imagens

Criar configuração de produção; revisar URL pública e SSR do Next.js, CORS, health/readiness, POSTS_SERVICE_URL, encerramento gracioso e secrets. Containerizar serviços externos usados. Publicar imagens com SHA/digest.

TECNOLOGIAS
Docker / Next.js / Express / Mongoose / Docker Hub

Desafio

Nome Docker não resolve no navegador; localhost entre VMs não representa outro serviço. Variáveis NEXT_PUBLIC podem estar congeladas no build.

Avançamos quando

Cada imagem inicia com configuração externa e todos os fluxos funcionam em ensaio local.

03

Criar a rede de homologação

Criar VPC e tiers entrada/app/dados quando disponíveis; alternativa: rede isolada com regras CloudStack e firewall nas VMs. Reservar IP público, configurar NAT e acesso administrativo VPN. Definir DNS HML.

TECNOLOGIAS
CloudStack Virtual Router / ACL / NAT / VPN / DNS

Desafio

Serviços dependem do network offering; rede bridge Docker só conecta containers do mesmo host.

Avançamos quando

Somente entrada pública; backend e banco privados; administração acessível pela rota autorizada.

04

Provisionar VMs e discos

Criar VM EDGE, APP e DB com Linux suportado pelo provedor; instalar Docker/Compose e aplicar configuração reproduzível via Ansible. Criar disco de dados separado, montar persistentemente e limitar logs.

TECNOLOGIAS
CloudStack Compute e volumes / Linux / Docker Compose / Ansible

Desafio

Cotas, CPU/RAM, IOPS e montagem após reboot; volume Docker sozinho não protege o host.

Avançamos quando

Reboot mantém montagem e serviços; capacidade e permissões verificadas.

05

Implantar MongoDB

Iniciar banco em rede privada, criar usuário limitado da aplicação, configurar autenticação/TLS, disco próprio e backup. Para o alvo HA, configurar três membros com dados em hosts físicos distintos.

TECNOLOGIAS
MongoDB / MongoDB Database Tools / disco persistente

Desafio

Versão/FCV da origem devem ser compatíveis com destino; mongo:7 do Compose não prova compatibilidade com Atlas.

Avançamos quando

Conexão privada funciona; recriação do container mantém dados; restauração isolada concluída.

06

Implantar o projeto completo em HML

Subir front, back e todos os serviços de eventos/perfil/posts necessários. Ajustar URLs internas para endereços privados ou DNS interno. Conectar banco HML e saída para Gemini/Logtail; validar destino dos uploads.

TECNOLOGIAS
Docker Compose / Next.js / Express / serviços do projeto

Desafio

Imagens adicionais e contratos de API precisam ser verificados nos outros repositórios. Arquivos de upload locais exigem armazenamento persistente/compartilhado.

Avançamos quando

Login, usuários, posts, mensagens, eventos, perfil, álbuns e IA usados pelo projeto funcionam em HML.

07

Publicar entrada HTTPS

Configurar Nginx: / para frontend; /api para backend principal; rotas dos demais serviços com prefixos sem conflito. Emitir certificado e configurar renovação. Manter 3000/5000/27017 sem acesso público.

TECNOLOGIAS
Nginx / TLS / DNS / ACME se aplicável

Desafio

Proxy deve preservar ou remover prefixos conforme a API. Validação ACME depende de DNS ou porta 80 controlada.

Avançamos quando

HTTPS válido, renovação ensaiada e acesso pelo navegador sem erros de CORS ou conteúdo misto.

08

Automatizar release

Manter Actions com build/testes/cobertura e SonarCloud; aguardar Quality Gate; produzir imagens por digest. Runner dedicado privado instala release em HML, valida e promove PROD com rollback. Substituir chamadas Render.

TECNOLOGIAS
GitHub Actions / SonarCloud / Docker Hub / runner privado / Ansible

Desafio

Evitar código não confiável no runner; imagem Next.js deve permitir promoção ou ser construída com configuração pública por ambiente.

Avançamos quando

Release HML comprovada; falha de readiness impede promoção; rollback de aplicação testado.

09

Instrumentar e ensaiar operação

Centralizar logs Winston/Better Stack; acrescentar Prometheus/Grafana e exporters se a equipe optar por operar métricas, ou serviço equivalente. Alertar HTTP, disco, memória, containers e banco. Definir RPO/RTO e retenção.

TECNOLOGIAS
Winston / Better Stack / métricas / backup externo

Desafio

Logs não substituem métricas. Backup deve ser consistente, protegido e restaurável; metas de RPO/RTO exigem validação.

Avançamos quando

Indisponibilidade gera alerta; restore e rollback cronometrados atendem às metas escolhidas.

10

Preparar produção e migrar dados

Reproduzir infraestrutura PROD com segredos próprios. Ensaiar dump/restore e medir janela. No corte, bloquear escritas na origem por todas as aplicações, gerar backup final consistente, restaurar e validar índices, documentos e relações.

TECNOLOGIAS
CloudStack PROD / mongodump / mongorestore / DNS

Desafio

Cópia com escritas ativas pode ser inconsistente. Não planejar migração sem conhecer tamanho, versão, permissões e origem real.

Avançamos quando

Validação pré-abertura completa; backup final preservado e plano de retorno definido.

11

Entrar em produção

Redirecionar domínio para entrada CloudStack e abrir tráfego/escritas somente no destino. Monitorar erros e fluxos; manter origem preservada e sem escritas durante observação; desativar legado após aceite.

TECNOLOGIAS
DNS / Nginx / CloudStack / monitoramento

Desafio

DNS pode ficar em cache. Após novas escritas no destino, voltar ao banco antigo exige reconciliar dados; rollback de imagem é diferente de rollback de banco.

Avançamos quando

Usuários acessam o projeto completo; todas as APIs/dados necessários estão no destino; alertas e backups operam.

12

Chegar ao alvo de alta disponibilidade

Adicionar APP B, MongoDB com três membros e entrada redundante; distribuir em hosts físicos diferentes e atualizar balanceamento. Validar estado compartilhado de uploads, caches Next.js e sessões; realizar testes de carga/falha.

TECNOLOGIAS
CloudStack anti-affinity / balanceamento / Docker / MongoDB replica set

Desafio

Mais VMs no mesmo host não entregam tolerância à falha física. Compose exige automação por host; Kubernetes é evolução opcional.

Avançamos quando

Perda de APP/DB/entrada testada sem exceder metas; nenhuma dependência de armazenamento local impede failover.

Arquitetura final de execução

Usuário → DNS → HTTPS 443 → entrada redundante
↓
CloudStack · redes privadas
APP A e APP B · Docker · frontend + backend + serviços necessários
↓
MongoDB replica set · 3 VMs · disco próprio por membro
Mídia persistente compartilhada, se houver uploads locais
↓
Backup externo + restore testado · métricas + alertas
Winston / Better Stack · Gemini API

GitHub → Actions / testes / SonarCloud → Docker Hub → runner privado → HML → validação → PROD / rollback

HA exige hosts físicos distintos e entrada redundante. Compose opera por host; não distribui containers automaticamente. Serviços externos em nuvem, como Gemini e SonarCloud, podem continuar externos ao CloudStack.

O que falta para executar

  • Conta/provedor CloudStack, zona, cotas, network offering, IP público e domínio.
  • Verificar código e imagens do frontend e microsserviços de eventos, perfil/álbuns e posts.
  • Inventariar versão, volume e origem dos dados, uploads e credenciais por ambiente.
  • Definir responsáveis, orçamento, janela de corte e metas de recuperação.

Entregáveis previstos: Compose por ambiente, Nginx/TLS, configuração Ansible, definição de infraestrutura, pipeline e procedimentos de migração/recuperação. Eles ainda precisam ser implementados; este documento descreve o caminho de execução.
