Controles de segurança
e como testá-los

Inventário baseado na implementação e nos testes encontrados no repositório. A existência de um controle ou teste não equivale, por si só, a uma auditoria completa nem garante a segurança da configuração de produção.

Revisado em 4 de novembro de 2026 · Testes não executados durante a elaboração deste relatório

Executar os testes

Abra o PowerShell na raiz do projeto e rode a suíte completa:

npm test -- --runInBand

Para rodar apenas um teste, por exemplo:

npm test -- --runInBand test/integration/noSqlInjection.spec.ts

O comando de build também verifica a compilação TypeScript, mas não substitui os testes de segurança:

npm run build
Ponto crítico: rate limit e clientes diferentes.

O login ainda tem limite de 5 tentativas por IP em 15 minutos; a validação de CPF usa 20 chamadas por IP por minuto. Se o proxy/hospedagem fizer todas as requisições parecerem vir do mesmo IP, pessoas em redes diferentes podem dividir o bloqueio. O limite geral da API usa o ID do JWT válido e, sem token válido, usa IP. É necessário validar o IP do cliente na hospedagem e testar com duas redes/contas. Não configure confiança em proxy sem conhecer a topologia.

Os limitadores usam armazenamento em memória, que não compartilha contadores entre processos/instâncias. As rotas de chat são montadas antes do limitador geral e não passam por ele.

Roteiro rápido de validação manual

  1. Execute a suíte automatizada e anote os testes que falharem.
  2. Use somente ambiente local/staging com banco e contas descartáveis.
  3. Teste tentativas sem autenticação, token inválido e token válido de outra conta.
  4. Para rate limit, use duas contas em redes distintas; exceda o limite em uma e confirme que a outra ainda consegue fazer login.
  5. Não teste injeção destrutiva nem faça carga em produção. Confirme em staging que as entradas maliciosas são rejeitadas e que registros legítimos continuam funcionando.
  6. Revise segredos de ambiente: chaves JWT, CPF/MFA e API keys devem ser fortes, distintas por ambiente e não versionadas no Git.
Relatório estático gerado a partir do código e dos testes presentes no repositório. A configuração de proxy, armazenamento distribuído do rate limit e comportamento da hospedagem precisam de validação no ambiente implantado.
